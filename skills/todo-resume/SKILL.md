# 待办续接（todo-resume）

解决「待办记了下次接不上」痛点。把待办固化成 `/opt/data/待办/` 下的结构化 md 文件（中文标题），要处理时读文件直接回到状态，无需重述上下文。

## When to Use
- 主人说「**看一下待办**」「**看看有什么待办**」「**待办列表**」 → 列出当前待办（快路径 0-token 直发，见下）
- 主人说「**处理待办/处理一下（某标题）**」「**继续（某待办）**」「**处理第N条**」 → 读对应文件回到状态并推进（按快照定位，见下）
- 主人说「**已完成待办/看已完成**」 → 列出已完成留档（独立快照）
- 主人说「**记个待办/记一下这个**」 → 按模板新建待办文件
- 主人说「**删掉/完成这条待办**」 → 标记完成、写总结、归档

## 快路径面板（2026-09-05，0-token 直发）

「看待办」「已完成待办」已接入 fast-command 快路径，不经 LLM 秒回：

- ha-ctl 硬编码 `cmd_todo` / `cmd_todo_done` → `todo_list.py --snapshot` / `--done --snapshot`
- 指令库 + fast-command `panel:true` 配置驱动放行；`_build_reply` 整份回显面板
- 快照锁定序号：面板发出时写 `.last_panel.json`（active）或 `.last_panel_done.json`（done），**处理第N条只读快照、不重新扫描**，防排序漂移
- 快照含 generated_at 时间戳；**超过 30 分钟按序号处理先提醒「面板已过期，重新看待办」**
- **查询 0-token（2026-09-05 主人反馈「查询不唤醒 agent」）**：fast-command 引擎1.6 匹配「第N条/看第N条」→ 直读快照回摘要（含标题/优先级/建档/摘要/文件名），**不唤醒 agent**；「处理N/继续N」才放行 agent 续接（需读写文件）
- 排版两行制（2026-09-05）：首行=序号+图标+标题+优先级，次行=📅建档+清洗后摘要（去 markdown 符号、截 45 字）

## 存储约定
- 目录：`/opt/data/待办/`（容器持久化，跨会话保留）
- 子目录：`已完成/` 存完结待办（带总结留档）
- 命名：中文标题做文件名，如 `观察RTK改写误伤.md`、`部署新影视站.md`
- 格式：Markdown，结构见「文件模板」

## 操作纪律（2026-09-02 主人纠错后固化，最高优先级）

1. **操作前强制 list 核对**：处理/编号/续接任何待办前，必须先 `todo_list.py` 列一遍，**按序号与标题逐一对应**，不凭印象猜哪条是哪条（曾把「第2条」错当成另一条，教训）。
   - ⚠️ 序号= `todo_list.py` 动态排序结果（优先级→建档时间→状态）；快路径面板发出时序号已被快照锁定（`.last_panel.json`），**处理第N条只读快照定位、不重新跑 list 重排**；快照过期则重新看待办刷新。
2. **建档/完结一次性写完整文件**：新建待办用 `write_file` 一次写全模板（含创建/状态/优先级/目标/当前状态/下一步）；完结时一次改到位——头部状态、总结、归档同步完成，禁止零敲碎打 patch 多次。
3. **状态三态清晰**：进行中 🟢（正在干）、观察中 👀（等结论，不动手）、已完结 ✅（移入 `已完成/` 并写总结）。待决策项不占这三态，单独标记 🤔（标题行用 ⚪ 图标区分）。⚠️ 头部 `- **状态**：` 行的值**只写状态词本身，禁带 emoji 尾缀、禁自造词**（emoji 语义放标题行表达；只允许 进行中/观察中/待决策/已完结 四个值）——todo_list.py 按整值精确匹配 ICON/ORDER 表，尾缀或自造词（如「验证中」「待处理」）整串匹配不上，列表显示 • 且排序失权，todo_reminder 还会按默认档误报超期。旧格式档案（无标准头部字段）处理时先补齐头部再继续。
4. **操作后刷新 list 核对**：每次建/改/完结后，重新跑 `todo_list.py` 核对列表是否反映真实状态——文件改了列表没跟上就是没做完。
5. **会话内同轮同步档案**：会话中完成某待办的工作时，同轮更新档案（当前状态+勾选 checkbox+补决策记录），不留给超期提醒器事后发现——工作做了档案没更，下次就被当「没及时更新」误报。
6. **勾 checkbox 前必须实测核实**：标记某项完成前查实际状态（grep 配置/跑命令验证），禁止因相关动作完成而推断勾选——相关收尾项（如 fallback 配置）可能独立存在且未做。
7. **超期先核会话再改档**：超期提醒命中或主人质疑「没更新」时，先 session_search 按待办主题搜会话记录核实是否已处理，证据分档（确凿已办/查无证据/有争议）后再更新或完结档案——档案滞后≠事情没做。

## 文件模板（含状态标签与头部字段）

```markdown
# <待办标题>

- **创建**：YYYY-MM-DD
- **状态**：进行中 / 观察中 / 待决策 / 已完结
- **优先级**：高 / 中 / 低

## 目标
一句话说明要达成什么。

## 当前状态
此刻进展到哪一步、卡在哪、已确认什么。

## 决策记录
- 已定的方案/选型（含理由）
- 待定项（主人未拍板的）

## 下一步
- [ ] 可执行的操作项（checkbox，处理时勾选）
- [ ] 要问主人的问题

## 关联
- 相关技能/文件/脚本/凭据键名（引用键名，勿明文）
- 相关会话（@session:... 链接回溯）
- 临时文件路径（完结时清理的散落中间产物，如 /tmp/xxx、/opt/data/tmp/xxx）
```

## 操作流程

### 1. 看待办列表（快路径或脚本）
```bash
python3 /opt/data/scripts/todo_list.py [状态筛选] [--snapshot]
python3 /opt/data/scripts/todo_list.py --done --snapshot   # 已完成留档
```
一条命令列出全部待办（**序号 + 状态图标 + 标题 + 优先级 + 建档时间 + 当前状态首行**），**按优先级动态排序**（高→中→低，同级按建档时间新→旧）。可带状态词筛选（如 `观察中`）。无需逐个 read_file。
- 状态图标：🟢 进行中 / 👀 观察中 / 🤔 待决策 / ✅ 已完结
- 快照文件：`/opt/data/待办/.last_panel.json`（active）、`.last_panel_done.json`（done），字段 `generated_at/scope/count/items[]`（items: seq/file/title/status/priority/created/summary）

### 1.5 查询某条待办（0-token 直回，2026-09-05）
主人说「第3条」「看第2条」等 → fast-command 引擎1.6 直读快照回摘要（不唤醒 agent）；**不要重新跑 todo_list.py 重排**。
若快照不存在/序号越界 → 插件回「先看待办生成」提示；agent 兜底时同规则。

### 2. 处理某项待办
1. 主人报序号（如「处理3」）：**先读快照** `/opt/data/待办/.last_panel.json` 或 `.last_panel_done.json`，按 `seq` 拿 `file` 定位——**不重新跑 todo_list.py 重排**（序号以主人眼前面板为准）
2. 快照超过 30 分钟：先提醒「面板已过期，重新看待办」再处理
3. **主人追问面板内容（非处理序号）**：先读 `/opt/data/state/last_panel.json`（fast-command 通用面板快照，含 trigger+全文）确认主人看的是哪张面板，再结合 `.last_panel*.json` 精细快照定位——不凭空猜
4. `read_file` 读对应 md（在 /opt/data/待办/ 或 /opt/data/待办/已完成/ 下）
5. 依据「当前状态 + 决策记录 + 下一步」直接续接，开始执行下一步
6. 推进后更新文件（改当前状态、勾选完成的下一步、补充新的决策/下一步）

### 3. 记新待办
按模板创建中文标题 md，填「创建日期/状态/优先级/目标/当前状态/下一步」，决策记录和关联可后补。

### 4. 完结待办（一条命令自动化，2026-09-02 新增）
```bash
python3 /opt/data/scripts/todo_finish.py <标题或序号> --summary "总结" [--clean-tmp] [--session <会话链接>]
```
脚本自动完成：追加 ## 总结 区段 → 校验「关联」路径（警告死引用）→ 清理标记临时路径（--clean-tmp）→ 头部状态改已完结 → 移入 `已完成/`。
- 可选 `--session <@session链接>`：总结区追加会话回溯链接
- 输出「建议记忆摘要」供主人确认，不自动写入 memory
- 重要产物临时文件提示主人确认后再删，不擅自删
- 序号与 todo_list.py 动态排序对齐（find_file 已修，2026-09-02 v2.3.1）

## 🔴 定时类任务：待办档案 + cron 绑定（2026-10-11 主人定，红队审查后固化）

任何「到期要主动推进」的任务（复盘/切换决策/试水验收/阶段性汇报），禁止只建 cron——cron 只是唤醒器，**那一次会话若失败/被删，事情就丢了**。标准结构三层：

1. **待办档案 = 事实源**：按模板建中文标题 md，存部署详情、决策记录、下一步清单、**回滚/分支路径写死在档案里**（不依赖唤醒时的临场判断）
2. **cron = 唤醒器**：prompt 首句固定为「处理待办『<标题>』」，**第一步必读档案文件再执行**（skills 绑 todo-resume）；即使唤醒是全新会话零记忆，读档案即完整续接
3. **超期提醒 = 兜底**：现有每日 9 点 todo_reminder 自动扫描，档案若一直没被推进会自己浮上来催

任何一环丢失，另两环仍能兜住。案例：`wb-proxy试水观察与切换决策`（cron 7760e2e6c98c 绑定）。

**适用范围写死：no_agent 自执行脚本同样落档案**——脚本自闭环（自行探测→自愈→推送→自停）≠ 免档案。档案承载脚本给不了的三样东西：①结果确认后的**收尾动作**（删 cron、完结待办、清理状态文件）；②cron 失踪/永不触发时的**分诊分支**（写死在档案里）；③每日 9 点超期提醒的**扫描对象**。cron 层形态差异：agent 唤醒型用「处理待办『标题』」prompt 绑定；no_agent 型脚本自执行、推送即结果。

**no_agent 看门狗分两型，档案形态不同（2026-11-01 主人定，纠正 2.4.1 一刀切）：**
- **临时观察型**（条件达成即收尾、有终点，如试水观察、token 到期窗口、验证期复核）→ 档案标 👀 观察中，进活动面板，等结论完结
- **常驻看门狗型**（永续运行、无「结论到来」之日，如温度预警/油价/车控四件套/上下线监控）→ **建档即完结**：一次性写成已完结+总结，直接落 `已完成/`，不进活动面板。⚠️ 标「观察中」会永久占位+被超期提醒误报+污染三态语义。档案只承载分诊层：cron ID、脚本路径、失踪分诊分支、停用方法；全局兜底由「定时任务状态监控」cron 承担

### 2.5 「哪些没及时更新」盘点（主人问更新状态时）
```bash
python3 /opt/data/scripts/todo_list.py
TODO_REMINDER_DRYRUN=1 python3 /opt/data/scripts/todo_reminder.py
```
先出超期清单（DRYRUN 守卫防误发卡），再逐条按操作纪律 7 用 session_search 核实是否实际已处理——核实结果按证据强度汇报（确凿已办=更新或完结档案；查无证据=如实报档案原文并问主人），不凭主人一句「早处理过了」就勾完结。

## 自动化：超期提醒（可选，已提供脚本）
- 脚本：`scripts/todo_reminder.py`，扫描待办文件，超过阈值天数未更新状态即输出提醒
- 部署方式：cron（no_agent）**每天 9 点**跑（2026-09-06 主人定：原每小时跑改每天一次防刷屏），有超期待办才推飞书卡片，否则静默
- **阈值按优先级分档（2026-09-02 升级）**：进行中 高3/中7/低14 天；观察中/待决策 高5/中10/低20 天
- 每条提醒自动带「→ 下一步」动作建议（从文件下一步区段提取第一个动作）
- ⚠️ 测试时须设 TODO_REMINDER_DRYRUN=1 防误发卡片（v2.3.1 守卫）

## 与现有体系的关系
- 记忆库（memory）存**精简常驻事实**；待办文件存**任务级厚上下文**——两者互补
- 完结待办时：结论精简进记忆，完整过程留档在 `已完成/`——记忆只留精华、不撑爆上下文
- 吸收 project-notes 思路：按项目/任务聚合上下文 + 可搜索 + 预置审查 prompt
- 比 todo 工具强：todo 会话级即焚，待办文件跨会话持久、可承载完整状态
- 比装 MCP 轻：无外部依赖、不引新进程，纯文件 + 复用现有读取工具
