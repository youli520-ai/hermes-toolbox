# 容器侧可回收项清单（按类别，非一次性事件）

盘点时的默认候选。每项**仍须逐项列给主人过目**，本表只说明「哪类东西属于可回收」及判定要点。

## 探针/测试产物
- 形如 `*_probe_data.bin`、`<前缀>_<日期>_<hash>_probe_*.png` 的文件散在工作目录与 Hermes 图像目录
- 判定：文件名带 probe/测试标记，且对应对话已结束
- 常见形态：单文件 7～9MB、成批几十个，累计数百 MB；单看一个不起眼，看总量才显形
- ⚠️ 同批的**真实产物**（本轮要交付给主人的文件）绝不能连带删——按文件名分类时先看清 `probe` 前后缀边界

⚠️ **「同 MD5 多份」清前必算，且要逐类算、不能只报一次**（2026-10-12 实测沉淀）：探针类产物反复跑同一批载荷，往往同一个文件存了 N 遍。清理前**对每一类分别算唯一 MD5 数与大小分布**——big7 102 份唯一 MD5=1、data 102 份唯一 MD5=1，而 note 103 份却有 2 个哈希（其中 1 份内容不同）。只报一个「唯一 MD5=1」会漏掉那份真差异，而它恰在你以为可以一起删的那一类里。

判据与动作：
- 唯一 MD5=1 且大小一致 → 同一载荷存了 N 遍，**保留最新 1 个批次、其余可删**，这是探针清理里最稳的一种
- 同类里出现第 2 个哈希 → 逐个 mtime 对比，确认哪份是当批次、哪份是历史残留，**别按哈希数直接下结论**
- 清理后**核验保留批次仍在位**（逐个 `os.path.exists`），并把删除清单落盘一份 JSON 供追溯

⚠️ **清完必须复核残留并逐项归因**：按 `*_probe_*` 通配清完后，目录里常还剩一批同名系文件，但它们**不是**探针产物——`*_probe_report.md`（批次报告）、`_probe_dot.png`/`_probe_busy.png`（早期其他探针类型）、`*_fixed.png`/`*_repaired.png`（恢复试验件）。清完 `ls` 复核残留清单并逐项说明「这是什么、为什么留」：不归因，主人无法判断你漏删还是误删；反过来把它们当垃圾一并删，会连报告与恢复试验件一起毁掉。

## 状态库与配置备份
- `state.db.bak-*`、`state.db.<profile>.bak-*`、`<profile>-state.db.bak-*`
- 判定：留最近 1～2 份，其余删；跨 profile 的备份各自归属本 profile，删 default 的不影响 profile-a/profile-b
- 注意：备份是**排障证据**。若同期正在查某 profile 的落库/损坏问题，那几份备份先留着
- ⚠️ **这一类往往是单笔里最大的一块**（同目录下几十份累积快照，件件看着一样大）。删之前先确认**正在用的那份是活的**（mtime 当天、体积正常），再按文件名筛——当前文件与旧快照外观相同，只凭「名字旧」判断会误删正在写入的那个
- 删完目录里常还剩 tar.gz/配置备份等其它类别（属未列入清单的项），一并核对一遍，别顺手连坐

## 已被取代的整包备份
- 迁移前、改名前的全量 tarball
- 判定：现行状态已稳定运行若干天、且同名资产已在新位置存在 → 已被取代
- ⚠️ **这类是主人的「回滚保险」，不是纯垃圾**。清单里要单独列出并标明放弃了什么回滚能力，**由主人决定**，不列入「默认零风险」那一档
- ⚠️ **迁移期整包常是 backups/ 里最大的一块**（实测三项合计 2.9G，而同目录其余可删项全是 MB 级），其余可删项清完对水位近乎无感。报数时点明「这是唯一能让 df 明显动的一项」，别和一堆 MB 级清理混在一起说

## webui 临时目录与散落报告文档（顶层重复出现的两类）

`/opt/data` 顶层会持续攒这两类，单看都不大但**数量多、命名带时间戳、无人回收**：

- `webui-*` 临时目录：`webui-bubble-<ts>` / `webui-docpreview-<ts>` / `webui-deck-<ts>` / `webui-diag-<ts>` / `webui-binprobe-<ts>` / `webui-mdimg-<ts>` / `webui-shot-<ts>` / `webui-v0-<ts>`——一次预览/一个气泡留一个目录，生命周期就是那一轮会话，属零风险档
- 散落报告文档：`报告-<ts>.docx` 平铺在根目录，几十份累积；判定同上（一次性产出、无索引）

⚠️ **这两类是「噪声级」的典型**：合起来常只有几 MB，对着上百 G 已用量水位基本不动（§1c）。删它们没错，但**汇报必须带量级**——报「已清理 N 项 / X MiB」，别让项数听起来像成果。

⚠️ **顶层散落的旧技能备份包/目录要先查引用，不能默认进零风险档**：`self-built-skills-backup.tar.gz`、`hermes_skill_backup/` 这类看着是历史包袱，**实则可能是某个修复脚本的回滚源或被技能 SKILL.md 索引的对象**（见本节末「名字像测试垃圾 ≠ 可以删」）。

## 缓存残留 tmp
- 形如 `.<name>_<random>.tmp` 的原子写残留，一次崩溃/中断留一个
- 判定：同名正式文件已存在 → tmp 可删；同名正式文件不存在 → tmp 可能是唯一副本，别删

## 轮转旧日志
- `*.log.1/.2/.3` 与 `errors.log.*`
- 判定：删 `.2` 及更早，保留 `.1` 与当前文件
- ⚠️ **`.1` 常是判据类体检的证据来源**（注册行随当前日志轮转后落进 `.1`），删掉会让「插件是否加载」类判定从「证据不足」退化成误判失效

## 名字像测试垃圾 ≠ 可以删（清测试文件/废弃包时必做）

清理 `/opt/data` 顶层这类散落的测试文件与废弃包时，**分类只是候选生成器，不是删除依据**。名字带 `test`/`tmp`/`probe`/`verify` 或后缀带 `.bak`/`.old`/`.tar.gz` 的东西，大比例仍然被活代码或技能文档引用——实测一轮 27 个候选里 7 个被引用，包括：

- `self-built-skills-backup.tar.gz` —— 看着是废弃备份，实为某个修复脚本的**回滚源**，删了那脚本就废了
- `fast_command_dryrun.py` / `tempfile_archive.py` —— 名字像临时测试，实为多个技能的**索引脚本**
- `host-b_temp_watch_state.json` —— 名字像临时状态，实为监控脚本的**运行时状态文件**
- `.probe_own/` / `.officecli/` —— 看着像空壳残留，实为**技能正在使用的目录**

**查引用的范围要比文件名所在目录宽得多**：只 grep 一个脚本目录会漏掉三类引用——被技能 SKILL.md 索引、被 cron 定义引用、被另一个脚本当回滚源。技能文档和跨 profile 副本才是引用主战场。

⚠️ **全树 `grep -rn` 会超时**（几分钟无输出）。正解是**先列出确定会被引用的文件集合，再拿候选名去匹配内容**：各 `scripts/` 目录下的 `.py`/`.sh`/`.mjs`、`cron/jobs.json`、`config.yaml`、三 profile 各自的 `SKILL.md`。几百个文件的量级秒级完成。

判定结果分两类写进清单，**逐条点名保留项及其引用方**——「挡下了哪些、为什么留」比「删了哪些」更能证明这次清理没越界。

## 跨卷迁移候选（删除之外的另一根杠杆）

删除项常是噪声级，真正能动水位的往往是**整块冷数据可以搬到空闲卷**。扫到大目录时先问一句「这块是不是该在别的盘上」，而不是直接判它可删。

- 典型：媒体库/音乐/归档下载目录落在告警卷，而系统里另有一块专门的大容量卷（容量健康、几乎空着）
- 判据：`df -h` 里存在挂载源不同、使用率低的卷，且该目录内容属于「放哪都能用」的冷数据
- **迁移只挪不删**，主人要的是数据还在、水位下去——**不能混进「可删」清单里一起批**，必须单独请示：迁还是留、落到哪个卷哪个目录
- 报数时给两根杠杆各自的合计（纯删除约 X / 若加迁移则约 X+Z），让主人一眼看出哪根才值得授权

⚠️ **同 inode 的两条路径不是两份空间**：`du` 按路径走，硬链接/绑定挂载/同一目录的两个入口会被算两遍。候选与其疑似副本先用 `stat -c '%i %n' A B` 比对，同号就在清单里标注「删一处不省空间」并按一份计。

## 判定顺序
1. 先按类别归拢，再逐项 `ls -lh` 确认大小与时间
2. 查引用：`grep -rln "<文件名>" <脚本目录> <cron 目录>`
3. `stat -c '%i'` 比对疑似重复路径，剔除双算
4. 大目录额外判一次「是否该在别的盘上」，是则进迁移候选而非删除候选
5. 剔除正在被写入的文件与其它 profile 的运行目录
6. 出一张「路径 + 大小 + 为什么可删」的表交主人；**没点头一律不执行 rm**

## 出方案：分档而不是平铺
别把十几项捆成一张平铺清单让主人从零判断——**归成「零风险」/「有取舍」/「需 root」三档，每档给出可回收量与代价，并把推荐的那档说清楚**。

- **零风险档**：纯历史快照、已确认无引用的副本
- **有取舍档**：主人的回滚保险、含真实产物的目录（工作文件、生图产物），**写清放弃的是什么**
- **需 root 档**：宿主侧卷级/快照/docker 层

主人对自己的数据有判断权；**agent 不代他选**。即使某一档明显更优，也要点名推荐并说明理由，而不是直接执行。主人当场只回一个字母/一个档位时，**执行范围严格限定在他点的那一档**，不连坐同目录的其它项。

## 排除项也要写出来
被排除的东西（如另一块分区上的大目录）**必须在结论里显式点名并说明为何无关**。只说「其余无需处理」会让主人以为漏扫了；写清「那 22G 在另一块盘上、水位健康、与本次告警无关」才是真的结论。
